# エージェント運用ルール（蒸留メモリ）

> 運用ルール: タスクに失敗したときは、原因を調査・検証した後、その教訓を
> **個別事例ではなく汎用ルール 1 行**（`RULE: ...`）に蒸留して下の「ルール一覧」に
> 追記すること。類似の既存ルールがある場合は新規追加ではなく統合すること。
> 実装タスクの開始時に必ずこのファイルを読むこと（CLAUDE.md「ループ規約」参照）。

## ルール一覧

- RULE: git・シェル操作は対象リポジトリを `git -C <絶対パス>` 等で毎回明示する。永続シェルの CWD に依存すると隣接リポジトリへの誤操作になる（2026-06-12: studio 側に player の remote を誤追加し誤 push 未遂、non-FF 拒否で実害なし）
- RULE: 外部プロセス・デーモンを待つ subprocess 呼び出しには必ず timeout を付け、常駐し得るエントリポイントには全体 deadline を置く。無限待ちは lock を握ったまま以降の全自動実行とリカバリを殺し、アラートも飛ばない（2026-07-07: docker info ハングで 4 日配信停止）
- RULE: プロセス名によるマッチング（ps の command 文字列など）は裸の部分一致にせず、トークン単位で「実行体（python 等）+ 対象パス」の組み合わせを要求する。裸の部分一致は `less scripts/foo.py` や `grep foo.py` のような無関係プロセスまで誤検出・誤 kill する（2026-07-10: watchdog レビューで検出）
- RULE: リトライ回数の上限は「回数 × (1 チェックの最悪所要時間 = subprocess timeout + interval)」で壁時計時間を検算し、上位の deadline より確実に短くする。回数だけの上限は障害時にチェック自体が遅くなって膨張し、deadline がフォールバック処理（自動復旧等）より先に発火して到達不能にする（2026-07-17: wedge 中の docker info 15s timeout × 90 回 = 1530s > deadline 1200s で wedge 自動復旧が発火せず配信失敗）
- RULE: SIGALRM 等プロセス内 deadline は自プロセスしか止められない。docker compose run 等の子プロセスを起動するエントリポイントでは start_new_session=True で子に独立 pgid を持たせ、deadline ハンドラから killpg で子ごと道連れにする設計にする（2026-07-10: deadline がハングした docker compose run を放置する穴をレビューで検出）
- RULE: health check が検知した異常のうち「その先の全処理が確実に失敗する」種類のものは、通知だけで済ませず後続フローを中断させる。検知して止めないと壊れた状態のまま最後まで走り、後片付け（翌日枠の予約等）まで道連れになる（2026-08-06: ディスク満杯を 06:45 に検知したがアラートのみで続行し、配信が live にならないうえ翌日枠の予約も失われた）
- RULE: 環境の枯渇リソース（ディスク空き・inode・メモリ等）は正常時も毎回 INFO ログに実測値を残す。枯渇は事後には痕跡が消えて（自動 purge 等で空きが戻る）原因特定が不能になる（2026-08-06: 満杯だった証拠が ENOSPC メッセージ 1 行しか残らず、何が食い潰したか特定できなかった）
- RULE: シェルで「一定時刻／一定時間まで待ってから次のコマンド」を書かない。条件式のエラーが待機のスキップとして現れ、後段が即時実行される。待機は回数ループ（`for i in $(seq 1 N); do sleep S; done`）か対象の状態ポーリングで表現する（2026-08-06: zsh の `[ "$(date +%H%M%S)" \< ... ]` がエラーになり stop が即発火、3分28秒の配信が2分で切れて不完全な VOD が公開された）
- RULE: 子プロセスの中断（sys.exit(1)）は、呼び出し側が戻り値を見て後続を止めて初めてガードになる。ガードを追加したら「誰がその終了コードを消費するか」を必ず追い、orchestrator 経路のテストで貫通を確認する（2026-08-27/28: prepare がディスク critical で exit 1 したが orchestrator が戻り値を捨てて start に進み、前日から Docker が生きていた偶然で配信された）
- RULE: 「通知しない」ことを検証するテストでは、実 FS / 実ネットワークに触る全チェック（ディスク空き等）をモックする。実機が異常状態のとき無関係テストが落ちて本命のデグレを見失う（2026-08-28）
